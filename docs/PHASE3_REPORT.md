# 第三阶段 Git 交付与验收

验证日期：2026-11-13。已实现本地 bare 仓库的独立初始化、冻结审批发布和事务恢复。没有创建 GitHub 仓库、连接网络远程、发布真实记录或部署 Pages。正式源码项目本身仍未初始化 Git，public 仍为零项目、零记录。

## 交付内容

- `scripts/initialize.py`：local-init 建立本地代码与空数据根提交；prepare 检查空 bare、main、唯一根提交和文件清单，生成初始化摘要；bootstrap 只推送已确认根提交，并创建仅限本地演练的启用凭据。
- `scripts/publish.py`：验证冻结批次、批准凭据、基准 HEAD、目标、工作区及暂存；备份原文件、保存写前日志，精确应用和暂存公开数据操作，创建带 Progress-Batch 标记和 noreply 身份的提交。
- `--recover-only`：提交前校验并恢复本批次，外部修改立即停止；提交对象已创建时复用对象；提交后不自动 reset，重新核验已有提交。
- 推送先查远程；拒收或结果不明可安全重试；已包含提交时直接确认成功；分叉时保留双方历史和证据，不 stash、rebase 或强推。
- `scripts/demo_git.py`：固定合成数据的一键演练，保留仓库、审批、备份、日志及冲突现场。

命令及恢复决策表见 [Git 操作说明](GIT_WORKFLOW.md)。现有五类业务 Schema 未改变；冻结验证与当前基准验证分离，以便恢复时验证已经产生的提交。

## 验证边界

当前发布器主动拒绝网络远程，只接受已初始化的本地 bare 目录。GitHub 认证、账户与仓库公开属性验证、首次 Pages 空站部署及外部发布启用仍属第四阶段；本地凭据明确记录 github_verified=false、pages_verified=false。

未实际运行 Python 3.14 或远程 CI；未模拟整机断电和文件系统损坏，也没有把本地拒收等同于真实 GitHub 网络中断。第二阶段的真实手机浏览器视觉验收限制保持不变，本阶段没有新增视觉验证。

初始化文件和典型凭据扫描不能证明所有文档、代码与 fixtures 都已脱敏，首次公开仍须审阅冻结文件清单。哈希和双锁检测意外修改，不抵御同一账户的恶意篡改，也不能阻止不遵守锁的外部 Git 进程；检测到不匹配时保留现场并停止。
